Pada mata kuliah Pemrograman Berbasis Kerangka Kerja (PBKK), kelompok kami membangun AsLab — Sistem Informasi Absensi dan Penilaian Praktikum, sebuah aplikasi desktop Rich UI berbasis C# WPF (.NET 10) dengan database SQL Server. AsLab membantu laboratorium mencatat absensi dan nilai praktikum, menghitung nilai akhir secara otomatis, membatasi akses sesuai peran, serta memberi peringatan dini terhadap praktikan yang berisiko tidak lulus.

Latar Belakang

Di banyak laboratorium, absensi dan nilai praktikum masih dicatat di spreadsheet terpisah untuk setiap kelas atau modul. Cara ini menimbulkan beberapa masalah:

  • Data tersebar di banyak file dengan format berbeda, sehingga rekap nilai akhir memakan waktu lama.
  • Rumus bobot nilai diketik manual oleh tiap asisten, sehingga rawan salah hitung dan tidak konsisten antarkelas.
  • Semua orang bisa mengedit seluruh sheet, dan perubahan nilai tidak meninggalkan jejak.
  • Praktikan yang terlalu sering absen baru ketahuan di akhir semester.

AsLab menyatukan semua data itu dalam satu aplikasi dengan aturan yang sama untuk semua kelas.

Fitur Utama

1. Login dan Keamanan

Setiap pengguna masuk dengan username dan password. Password disimpan sebagai hash BCrypt, bukan teks asli, dan semua query ke database berparameter melalui Entity Framework Core. Bila username atau password salah, aplikasi menampilkan pesan yang jelas.

2. Dashboard Real-Time

Dashboard menampilkan empat kartu statistik (total praktikan, kelas aktif, modul berjalan, rata-rata kehadiran), grafik batang rata-rata nilai per modul, grafik donat distribusi nilai huruf, daftar praktikan berisiko, dan aktivitas terbaru. Semua angka dihitung langsung dari database, bukan angka statis. Pengguna juga bisa beralih ke tema gelap.

3. Data Praktikan

Koordinator dapat menambah, mengubah, dan menghapus data praktikan, mencari berdasarkan NRP atau nama, memfilter berdasarkan kelas, angkatan, dan status risiko, serta mengimpor banyak praktikan sekaligus dari file CSV. Input yang salah langsung ditolak dengan pesan yang menjelaskan cara memperbaikinya, misalnya NRP yang tidak berisi 10 digit angka.

5. Absensi

Asisten memilih kelas dan modul, lalu menandai status Hadir, Izin, Sakit, atau Alpa untuk setiap praktikan. Tersedia tombol "Tandai semua hadir" agar pencatatan cepat. Kehadiran dihitung dengan rumus Hadir ÷ (Hadir + Alpa), sehingga izin dan sakit tidak menurunkan persentase kehadiran.

6. Input Nilai dengan Komponen yang Bisa Diatur

Setiap mata praktikum memiliki komponen nilai sendiri, misalnya Pretest 20%, Praktik 50%, dan Laporan 30%. Koordinator bisa menambah, mengganti nama, atau mengubah bobot komponen di halaman Pengaturan, dan kolom di halaman Input Nilai menyesuaikan secara otomatis. Nilai modul langsung terhitung saat angka diketik. Bila ada angka di luar 0–100, sel berubah merah dan tidak ada nilai yang disimpan sampai semuanya diperbaiki.

Halaman Rekap Nilai menampilkan nilai setiap modul, nilai sementara, nilai akhir, huruf mutu, kehadiran, dan status kelulusan. Praktikan berisiko diberi tanda ⚠. Aturan Perhitungan Nilai

  • Nilai modul = jumlah (skor komponen × bobot komponen) ÷ 100. Contoh: Pretest 80, Praktik 90, Laporan 70 dengan bobot 20/50/30 menghasilkan 82.00.
  • Nilai akhir = rata-rata nilai modul dari seluruh modul; modul tanpa nilai dihitung 0.
  • Huruf mutu: A ≥ 86, AB ≥ 76, B ≥ 66, BC ≥ 61, C ≥ 56, D ≥ 41, E < 41.
  • Status: kehadiran di bawah 75% berarti "Tidak Memenuhi Syarat"; selain itu lulus bila nilai akhir ≥ 56.
  • Praktikan berisiko: kehadiran < 75% atau nilai sementara < 56, sehingga bisa ditindaklanjuti sebelum semester berakhir.

Kode dibagi dalam lapisan yang jelas: View (XAML) → ViewModel → Service → Entity Framework Core → SQL Server. Semua aturan bisnis dan pengecekan hak akses berada di lapisan service, sehingga mudah diuji dan dikembangkan.

Arsitektur aplikasi AsLab.

Rancangan Database

Database terdiri dari 13 tabel, di antaranya users, mata_praktikum, komponen_nilai, kelas, modul, jadwal_modul, praktikan, absensi, nilai, nilai_komponen, dan log_aktivitas. Tabel dibuat otomatis lewat EF Core Migrations saat aplikasi pertama kali dijalankan, dan tersedia juga skrip T-SQL (schema.sql) untuk membuat tabel secara manual di SQL Server Management Studio. Aturan penting dijaga langsung oleh database, misalnya NRP unik berisi 10 digit dan skor harus 0–100.

Pengujian

Seluruh skenario uji di PRD (TC-01 sampai TC-14) dan aturan bisnis diotomatisasi dengan xUnit, misalnya login dengan password salah, NRP ganda, nilai 105, perhitungan nilai 82.00, asisten yang mencoba membuka kelas lain, kelas yang sudah dikunci, export Excel/PDF, dan import CSV. Saat laporan ini ditulis, 62 tes lolos pada SQL Server.

Kesimpulan

AsLab menggantikan spreadsheet terpisah dengan satu aplikasi yang menghitung nilai secara konsisten, membatasi akses sesuai peran, mencatat setiap perubahan nilai, dan mengunci nilai setelah difinalisasi. Dashboard dan daftar praktikan berisiko membantu koordinator serta dosen menindaklanjuti masalah lebih awal. Pengembangan selanjutnya dapat berupa notifikasi email untuk praktikan berisiko, impor data langsung dari sistem akademik, dan versi web agar praktikan dapat melihat nilainya sendiri.
